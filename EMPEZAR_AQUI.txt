TrabajaYA - backend consolidado

Aquí entrego solo el backend. El frontend se conserva en su repositorio separado.

1. Leer README.md para ver alcance y estado real de verificación.
2. Copiar el contenido en una rama del backend actual. Conservar la carpeta .git
   del usuario y sus configuraciones privadas; no borrar datos.
3. Subir Dockerfile, src, docs, .specify, specs y .github. No subir secretos.
4. Seguir docs/DESPLIEGUE.md para Render Free + Aiven + Supabase.
5. Completar las variables después, directamente en Render. El ZIP no conecta
   automáticamente a las cuentas del usuario.

No se requiere ejecutar otra prueba local para continuar. GitHub Actions esta
preparado para compilar y verificar en la nube. No se ha ejecutado ese workflow aún.

Incluye README en primera persona, constitución, especificación, plan, tareas,
trazabilidad, pruebas, decisiones y guion de demo en Markdown.

Los artefactos no reemplazan los commits, pull requests ni la evidencia real de
Spec Kit. La rúbrica de grupo requiere confirmar la modalidad individual.

El informe docs/VERIFICACION.md diferencia lo comprobado y lo pendiente.
